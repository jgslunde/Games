"""
ENCIRCLEMENT RULE IMPLEMENTATION FOR HNEFATAFL
===============================================

Overview:
---------
Hnefatafl includes a special win condition not present in Brandubh or Tablut:
If the attackers form a continuous chain that completely surrounds the king
(and any defenders connected to him), the attackers win immediately.

Algorithm:
----------
The implementation uses an efficient flood-fill algorithm with the following logic:

1. Find the king's position on the board
2. Start a flood-fill from the king's position
3. The flood-fill can traverse through:
   - Empty squares
   - Defender pieces
   - The king itself
4. The flood-fill CANNOT traverse through attacker pieces
5. If the flood-fill reaches any edge of the board (row 0, row 10, col 0, or col 10),
   the king is NOT encircled
6. If the flood-fill completes without reaching an edge, the king IS encircled

Time Complexity: O(n) where n is the number of squares checked (at most 121 for 11x11 board)
Space Complexity: O(n) for the visited set and stack

Implementation Details:
-----------------------
- Method: `_is_king_encircled()` in hnefatafl.py
- Called during: `_check_game_over()` after every move
- Returns: Boolean indicating if king is encircled
- Effect: Sets game_over=True and winner=ATTACKER_PLAYER if encircled

Key Features:
-------------
1. Handles irregular shapes: The attacker ring doesn't need to be a perfect circle
2. Includes defenders: Any defenders connected to the king are part of the enclosed group
3. Requires complete encirclement: Even a single gap allows the king to "escape"
4. Efficient: Uses simple flood-fill rather than complex graph algorithms

Testing:
--------
Comprehensive tests in test_encirclement.py verify:
- Starting position is not encircled
- Simple box encirclement works
- Encirclement with defenders inside works
- Breaches in the wall prevent encirclement
- Paths through empty squares prevent encirclement
- Complex irregular shapes work correctly
- Game over is triggered properly

Example Scenarios:
------------------

Encircled (Attackers Win):
   3 │· · · ○ ○ ○ ○ ○ · · ·
   4 │· · · ○ · ● · ○ · · ·
   5 │· · · ○ ● ♔ · ○ · · ·
   6 │· · · ○ · ● · ○ · · ·
   7 │· · · ○ ○ ○ ○ ○ · · ·

Not Encircled (Gap at top):
   3 │· · · ○ ○ · ○ ○ · · ·  <- Gap here
   4 │· · · ○ · ● · ○ · · ·
   5 │· · · ○ ● ♔ · ○ · · ·
   6 │· · · ○ · ● · ○ · · ·
   7 │· · · ○ ○ ○ ○ ○ · · ·

Integration:
------------
The encirclement check is automatically performed:
- After every move in `_check_game_over()`
- Before checking for stalemate
- Works seamlessly with MCTS and neural network training
- No special handling needed in training or gameplay scripts

Performance Impact:
-------------------
- Minimal: O(n) flood-fill is very fast for 11x11 board
- Only runs once per move during game over check
- Early exit if edge is reached (common case)
- No noticeable impact on training or gameplay speed
"""
